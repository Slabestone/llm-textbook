## 实验对象与固定参数

| 项目 | 值 |
|---|---|
| 模型 | 4-token `A/B/C/D` 条件 Bigram，logits `W[context,next]` |
| 可训练参数 | 4×4 = 16 |
| 数据 | 同一固定条件转移表，训练/验证/测试独立抽样；相同 token 配对值可重复 |
| 样本量 | 训练 32，验证 400，测试 400 |
| 随机种子 | 19、23、29（训练/验证/测试） |
| 优化 | 全批量交叉熵、解析梯度、SGD，学习率 1.0 |
| 训练步 | 0—120；35 步后只是**反事实参考延长轨迹** |
| 早停规则 | `patience=12`，`min_delta=1e-4` |
| 选择的检查点 | 第 **23** 步 |
| 停止条件触发 | 第 **35** 步 |

### 容易误解的一点：第 23 步并非曲线的绝对最低点

数据中第 23 步验证损失为 **0.76926393145306**；第 24 步为 **0.76917712326341**，后者略低约 `0.0000868082`。但是，早停规则要求一次改进**至少达到** `min_delta = 0.0001` 才更新“最佳检查点”；第 24 步未达到这一阈值，因此规则保留第 23 步，并于第 35 步触发停止。

所以图中的虚线应称为**「按早停规则选出的检查点（23）」**，而不是「验证损失曲线的数学绝对最小点」。这是一项规则与数值最小值之间的精度区分，不是程序错误。

### 模型与结论的边界

这是一份 **16 参数 Bigram 教学实验**，不是 Transformer 或大模型预训练数据。曲线证实：在这个固定抽样下，继续降低训练损失可能使验证损失上升，验证集可用于检查点选择；但单次随机种子不能证明所有任务上早停优于充分训练。测试集不参与梯度或检查点选择。
